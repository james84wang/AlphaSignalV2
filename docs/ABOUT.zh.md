## 概览与范围

AlphaSignal 是一款**个人使用**的网页应用，用于分析美股并构建/调优一套**仅做多的波段交易策略**。它**不是**商业软件，**不构成**投资建议，也**不适用于**日内交易。它基于日线数据运行，仅供个人研究使用。

应用通过**隐藏背离汇合（Hidden-Divergence Confluence）**引擎对可配置的美股股票池进行扫描——在 EMA-50/200 上升趋势中，当出现隐藏看涨背离并满足加权入场汇合分值时**买入**回调中的更高低点；当出现常规看跌背离 / DeMark 衰竭信号时**卖出**。用户可调整每个指标的分值以及买入/卖出阈值，并对结果进行历史回测。

---

### 架构与技术栈

```
浏览器
  └─ React 18 + Vite + TypeScript 单页应用
        ↕ HTTP (REST JSON)
Python FastAPI 后端（端口 8000）
  ├─ 信号引擎  （确认枢轴 → MACD/RSI 背离 + DeMark + EMA 趋势门槛 → 汇合分值）
  ├─ 回测引擎  （仅做多的逐日组合模拟）
  ├─ 优化器    （Optuna TPE 搜索入场/出场分值与阈值，含过拟合检验）
  ├─ APScheduler  （可选的每日自动扫描）
  └─ 存储
        ├─ SQLite  （运行记录、信号、自选股列表、回测结果）
        └─ Parquet  （价格缓存，每个标的一个文件）
```

**后端：** Python 3.11+、FastAPI、uvicorn、pandas、numpy、yfinance、pydantic v2、PyYAML、SQLAlchemy/SQLite、pyarrow、httpx、APScheduler、Optuna（优化器）

**前端：** React 18、Vite、TypeScript、Tailwind CSS、lightweight-charts（TradingView 授权图表组件）、TanStack Query、react-router-dom、SheetJS（xlsx 导出）

**每日流程：** APScheduler（或手动触发）→ 拉取/更新 Parquet 价格缓存 → 为每个标的计算汇合信号 → 将 Run + Signal 记录写入 SQLite → 前端按需读取

## 策略细节

AlphaSignal 实现了一套**仅做多**的波段策略：**隐藏背离汇合 — 上升趋势波段**。它在确立的上升趋势中寻找回调**入场**点，并基于衰竭进行**出场**。所有计算都基于**已确认的K线**，因此信号可靠但会在实际转折后滞后若干根K线。

> **思路：在更高低点入场，在更高高点出场。**

---

### 关键概念 — 隐藏背离 vs 常规背离

背离 = 价格与动量在相邻摆动枢轴上方向不一致。

| 形态 | 价格表现 | 动量表现 | 含义 | 用途 |
|---|---|---|---|---|
| **隐藏看涨** | 更高低点 | 更低低点 | 回调抛压衰竭 → 上升趋势恢复 | **入场** |
| **常规看跌** | 更高高点 | 更低高点 | 顶部涨势衰竭 | **出场** |

动量由 **MACD 线** 和 **RSI** 读取（两个独立视角）。

---

### 趋势门槛（仅限入场）

除非当前K线同时满足以下全部条件，否则入场引擎**关闭**：

- EMA-50 **高于** EMA-200（多头结构）
- EMA-50 **上升**（相对 `slope_lookback` 根K线之前）
- EMA-200 **上升**
- 收盘价 **高于 EMA-200**

刻意**不要求**价格高于 EMA-50——健康的回调会触及快线，而这正是最佳更高低点形成的位置。**出场不设门槛**——因为趋势开始破坏时你可能正持仓。

---

### 入场分值（买入）

当满足：(1) 趋势门槛为真，(2) 本K线确认出现隐藏看涨背离（MACD 或 RSI），(3) 入场分值达到阈值时，触发**买入**。每个组件若在入场汇合窗口内触发，则计入其分值。

| 组件 | 默认分值 | 含义 |
|-----------|:------:|-----------|
| MACD 隐藏看涨背离 | 35 | 核心逻辑（MACD 动量） |
| RSI 隐藏看涨背离 | 35 | 核心逻辑，不同视角 |
| RSI 回调区间（40–55） | 20 | 位置过滤——确认健康回调 |
| DeMark TD9 买入结构 | 10 | 下行衰竭加成 |
| **买入阈值** | **65** | 分值需达到此值才触发买入 |

入场始终至少需要一个真正的背离——任何单一辅助指标都无法独自触发买入。将阈值提高到 70 可强制要求*两个*背离（更少、更高确信度的信号）；降低到 55 可提高频率。

---

### 出场分值（卖出）

当满足：(1) 本K线确认出现看跌背离 / DeMark 卖出事件，(2) 出场分值达到（较低的）阈值时，触发**卖出**。出场所需的证据**少于**入场——以更少的证据保护资金，而以更多的证据投入资金。

| 组件 | 默认分值 | 含义 |
|-----------|:------:|-----------|
| DeMark TD13 卖出计数 | 40 | 强烈的上行衰竭 |
| MACD 常规看跌背离 | 35 | 顶部动量 |
| RSI 常规看跌背离 | 35 | 顶部动量 |
| DeMark TD9 卖出结构 | 20 | 上行衰竭 |
| **卖出阈值** | **35** | 分值需达到此值才触发卖出 |

任一单一看跌背离（35）或一个 TD13 计数（40）即可独自触发出场；单独的 TD9 卖出（20）需要搭档。

---

### 汇合窗口与冷却

各组件几乎不会在*同一*根K线上同时达到峰值（MACD 与 RSI 枢轴不同；DeMark 按自身节奏完成）。因此每个组件若在**汇合窗口**内出现，即计入分值——入场默认 **10 根K线**，出场默认 **5 根K线**。一个等于入场窗口的**冷却**机制可防止同一段回调重复触发买入。

---

### 指标

- **EMA-50 / EMA-200** — 定义趋势结构与斜率（趋势门槛）。
- **MACD（12/26/9）** — 背离基于 MACD 线测量。
- **RSI（14）** — 用于背离以及 40–55 回调区间过滤。
- **摆动枢轴** — 只有在右侧出现 `right` 根K线后才确认的摆动高低点。这使信号**不重绘**（但滞后）。
- **DeMark TD 序列（简化版）** — 趋势衰竭计时器：**TD9 结构**为9根连续合格收盘；**TD13 计数**为结构后13根合格收盘。TD9 买入加成入场；TD9 卖出与 TD13 卖出驱动出场。

所有分值、阈值、汇合窗口和指标参数都可在**设置**中编辑，并存储于 `config.yaml`。

---

### 策略局限

- **仅日线** — 不预测日内波动；无法对日内新闻作出反应。
- **设计上滞后** — 枢轴在实际高低点之后若干根K线才确认（不重绘的代价）。日线波段下1–5根K线的滞后可接受。
- **DeMark 为简化版** — 结构 + 计数及基本取消；省略了 perfection/recycle 等细节。
- **震荡市的来回打脸风险**；EMA-50/200 趋势门槛可减轻但无法消除。
- **用户调优的分值可能过拟合**校准期——请使用优化器的过拟合检验与样本外验证。
- **不含基本面** — 财报意外、指引与宏观事件不在模型中（仅有可选的财报静默期）。

## 回测细节与局限

回测引擎模拟一个**仅做多**的逐日组合——按时间顺序处理每个交易日，仅使用截至当日收盘可得的信息，并在*次日*开盘成交。

---

### 回测如何运作

#### 信号与成交时点（无前视偏差）

> 第 **T** 根K线的信号仅使用 0 … T 的数据（仅确认枢轴）。
> 入场与出场指令在第 **T+1 根K线开盘价** 成交。

#### 组合模拟

| 参数 | 默认值（config.yaml 配置） |
|-----------|:---:|
| 初始资金 | $100,000 |
| 仓位大小 | 当前净值的8% |
| 最低仓位 | $2,000 |
| 单只资金上限 | 净值的30% |
| 最大同时持仓 | 15 |
| 每日按分值取前N候选 | 10（按入场汇合分值排序） |
| ATR 止损倍数 | 1.5 × 14周期 ATR |
| 移动止损 | 是——用当日收盘价上移 |
| 止损后再入场冷却 | 5 根K线 |

**入场选择：** 每天所有新的**买入 / 强力买入**信号按入场汇合分值排序（越高确信度越高）。仅前10名候选进入槽位与资金检查，并在次日开盘成交。

**出场：**
- **ATR 止损**日内触及（对照日内高/低检查）→ 在止损价成交，若跳空则按开盘价
- 持仓出现**卖出信号** → 次日开盘成交
- **数据结束** → 按最后一根K线收盘价平仓

#### 费用（已配置）

| 参数 | 数值 |
|-----------|:-----:|
| 每股费用 | $0.005 |
| 每笔最低 | $1.00 |
| 每笔最高 | 交易额的1% |
| 收取时点 | 入场**和**出场均收 |
| 滑点 | 成交价应用0.1% |

#### 基准

从首个可得开盘价**买入并持有 QQQ**，持有至期末。使用复权总回报价格（含股息），以便与策略可比。

#### 价格基准

策略与基准均使用 **yfinance 复权价格**（`auto_adjust=True`）——历史价格按拆股与股息复权，因此回报反映含股息的总回报。

---

### 策略优化器（具备过拟合意识）

`scripts/optimize.py` 使用 Optuna（TPE）搜索入场/出场组件分值、买入/卖出阈值以及（可选）汇合窗口，然后对优胜配置进行压力测试：

- **70/30 样本内/样本外划分** 与 **4折前向（walk-forward）** 验证。
- **运气审计**（优胜者击败 QQQ 的频率是否高于随机配置）、**扰动测试**（是否能承受 ±10 分的分值扰动）以及**头部配置聚类检查**。
- 实时 `config.yaml` **绝不**自动修改；优胜者写入 `config.candidate.long.yaml` 供人工审核。

---

### 回测局限

- **数据延迟与粒度：** 仅日线；yfinance 数据可能延迟约1小时。不适合当日决策或日内择时。

- **预热期：** EMA-200 趋势门槛需要200根K线，摆动枢轴还会增加确认滞后，因此任何窗口的前几个月信号很少或没有。

- **幸存者偏差（重要）：**
  标普500、中盘400、小盘600 的股票池列表反映*当前*成分股。在回测期间**退市、破产或被剔除**的公司不在其中——使结果看起来好于真实情况（「虚高」向上偏差）。修正这一点需要历史时点成分数据（免费不可得）。请将所有回测回报视为**乐观的上限**。

- **未建模流动性或市场冲击：** 流动性差的小盘股买卖价差可能很大。0.1% 滑点假设对此类标的可能偏乐观。

- **未建模借券成本或税费。**

- **公司行为**仅通过复权价格处理。并购、分拆和代码变更可能造成数据缺口或不连续。

- **过往表现不预示未来结果。本回测仅供个人研究与策略理解使用——不构成投资建议。**
